## 1. POST /v3/files/file-upload-url

**用途**：获取文件上传预签名 URL（第一步），第二步使用 PUT 将文件流上传至返回的 `fileUploadUrl`。

**接口类型**：REST（由旧文件服务 file-and-template3 提供，ePaaS 网关代理层转发）

### 1.1 请求参数（入参）

| 参数名                     | 位置   | 类型      | 必填 | 默认值     | 说明                                                                                         | 优先级     | 备注     |
| ----------------------- | ---- | ------- | -- | ------- | ------------------------------------------------------------------------------------------ | ------- | ------ |
| `contentMd5`            | body | string  | 是  | —       | 文件内容的 MD5 值                                                                                | L1      | <br /> |
| `contentType`           | body | string  | 是  | —       | 文件 MIME 类型，枚举：`application/octet-stream`、`application/pdf`                                 | L1      | <br /> |
| `fileName`              | body | string  | 是  | —       | 文件名称，需含真实后缀，最长 100 字符，禁用特殊字符 \`/:\*"<>                                                     | L1      | <br /> |
| `fileSize`              | body | long    | 是  | —       | 文件大小（字节），总大小 ≤ 50MB                                                                        | L1      | <br /> |
| `convertToPDF`          | body | boolean | 否  | false   | 是否转换为 PDF（Word 等非 PDF 文件用于签署时需设为 true）                                                     | L1      | <br /> |

### 1.3 关键错误码

| 错误码     | 说明                                                 |
| ------- | -------------------------------------------------- |
| 1435002 | 参数错误：contentMd5/contentType/fileName/fileSize 不能为空 |
| 401     | 鉴权失败                                               |
| 403     | IP 白名单不匹配                                          |

### 1.4 兼容性说明

此接口实际由旧文件服务（file-and-template3）处理，ePaaS 网关代理层转发。需验证 ePaaS 调用旧文件服务的连通性及响应字段兼容。

## 2. POST /v3/sign-flow/create-by-file

**用途**：基于已上传的合同文件发起签署流程（含参与方、签名域配置）。M-1 最复杂的接口。

**接口类型**：REST

**L1 约束**：签署方 1～2 个、单份合同文件、指定位置签署、标准印章、支持短信验证码/免认证

**注意**：一个签署流程中所有 signer 的个人和机构不能超过 300 个。

## 8. Webhook: SIGN\_FLOW\_COMPLETE

**用途**：签署流程状态变更时由 ePaaS 主动推送给客户配置的回调地址。触发场景：autoFinish=true 全部签完自动完结、autoFinish=false 调用 finish 成功、任一方拒签、截止日到期、发起方撤销。

**接口类型**：Webhook（服务端主动推送）

**推送方向**：ePaaS → 客户回调地址（`signFlowConfig.notifyUrl`）

### 8.1 推送参数（出参 / Payload）

| 字段名                  | 类型     | 必填    | 说明                                           | 优先级 | 备注     |
| -------------------- | ------ | ----- | -------------------------------------------- | --- | ------ |
| `action`             | string | **是** | 固定值 `SIGN_FLOW_COMPLETE`                     | L1  | <br /> |
| `timestamp`          | int64  | **是** | 推送时间戳（Unix 毫秒）                               | L1  | <br /> |
| `signFlowId`         | string | **是** | 签署流程 ID                                      | L1  | <br /> |
| `signFlowTitle`      | string | **是** | 签署流程标题                                       | L1  | <br /> |
| `signFlowStatus`     | string | **是** | 流程状态：`"2"`-已完成，`"3"`-已撤销，`"5"`-已过期，`"7"`-已拒签 | L1  | <br /> |
| `statusDescription`  | string | **是** | 当流程非签署完成，其他原因结束时，附加原因描述                      | L1  | <br /> |
| `signFlowCreateTime` | int64  | **是** | 创建时间（Unix 毫秒时间戳）                             | L1  | <br /> |
| `signFlowStartTime`  | int64  | **是** | 启动时间（Unix 毫秒时间戳）                             | L1  | <br /> |
| `signFlowFinishTime` | int64  | **是** | 完成/结束时间（Unix 毫秒时间戳）                          | L1  | <br /> |

### 8.2 兼容性要求

- 字段结构、枚举值、推送时机必须与旧系统一致
- 客户侧回调地址配置逻辑不变
- signFlowStatus 枚举值必须对应旧系统的值：2（签署中/已完成）、3（已撤销）、5（已过期）、7（已拒签）

> **注意**：OpenAPI 规范中 signFlowStatus 的枚举描述为 `2-已完成`，但参考文档 §4.3 中描述为 `2 签署中 / 3 完成 / 5 撤销 / 7 过期`。**两处不一致，需 PM 确认**。
