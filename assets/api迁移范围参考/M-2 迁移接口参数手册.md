## 1. POST /v3/sign-flow/{signFlowId}/revoke

**用途**：撤销签署中的流程，撤销后变为已撤销状态。当签署方已完成签字盖章后撤销存在法律风险，必须先获得全部已盖章签署方同意。

**接口类型**：REST（后置操作类，按 signFlowId 归属路由，详见附录 C）

### 1.1 请求参数（入参）

| 参数名            | 位置   | 类型     | 必填 | 默认值 | 说明            | 优先级 | 备注     |
| -------------- | ---- | ------ | -- | --- | ------------- | --- | ------ |
| `signFlowId`   | path | string | 是  | -   | 签署流程 ID       | L1  | <br /> |
| `revokeReason` | body | string | 否  | -   | 撤销原因，最长 50 字符 | L1  | <br /> |

### 1.2 响应参数（出参）

| 字段名       | 类型            | 说明         | 优先级 | 备注     |
| --------- | ------------- | ---------- | --- | ------ |
| `code`    | int32         | 业务码，0 表示成功 | L1  | <br /> |
| `message` | string        | 业务信息       | L1  | <br /> |
| `data`    | object / null | 空对象        | L1  | <br /> |

### 1.3 关键错误码

| 错误码     | 说明                          |
| ------- | --------------------------- |
| 1435001 | 流程不存在或无权限                   |
| 1435002 | 参数错误：signFlowId 不存在或状态不允许撤销 |
| 1435003 | 业务规则冲突：流程状态不允许撤销（如已完结/已撤销）  |
| 401     | 鉴权失败                        |
| 403     | IP 白名单不匹配                   |

### 1.4 兼容性说明

- 撤销后流程状态置为「已撤销」（signFlowStatus=3），通过 M-1 已覆盖的 `SIGN_FLOW_COMPLETE` Webhook 推送（statusDescription="3"）。
- 仅指定发起方经办人场景才支持 e签宝 SaaS 官网撤回；默认平台方发起仅能通过接口撤销。
- **法律风险约束**：签署方已盖章后撤销，ePaaS 须 1:1 还原旧系统的"须获全部已盖章签署方同意"校验逻辑，不得放宽。

## 2. POST /v3/sign-flow/{signFlowId}/urge

**用途**：向当前轮到签署但还未签署的签署人发送催签提醒，支持指定签署人。

**接口类型**：REST（后置操作类，按 signFlowId 归属路由）

### 2.1 请求参数（入参）

| 参数名             | 位置   | 类型     | 必填 | 默认值 | 说明                                           | 优先级 | 备注     |
| --------------- | ---- | ------ | -- | --- | -------------------------------------------- | --- | ------ |
| `signFlowId`    | path | string | 是  | -   | 签署流程 ID                                      | L1  | <br /> |
| `noticeTypes`   | body | string | 否  | -   | 催签通知类型（英文逗号分隔）：1-短信，2-邮件，3-钉钉，5-微信，6-企微，7-飞书 | L1  | <br /> |
| `urgedOperator` | body | object | 否  | -   | 指定催签对象（详见 §2.1.1）；不传则催当前轮到的所有签署人             | L1  | <br /> |

#### 2.1.1 urgedOperator

| 参数名          | 类型     | 必填 | 默认值 | 说明                      | 优先级 | 备注     |
| ------------ | ------ | -- | --- | ----------------------- | --- | ------ |
| `psnAccount` | string | 否  | -   | 个人账号标识（与 psnId 二选一）     | L1  | <br /> |
| `psnId`      | string | 否  | -   | 个人 ID（与 psnAccount 二选一） | L1  | <br /> |

### 2.2 响应参数（出参）

| 字段名       | 类型            | 说明         | 优先级 | 备注     |
| --------- | ------------- | ---------- | --- | ------ |
| `code`    | int32         | 业务码，0 表示成功 | L1  | <br /> |
| `message` | string        | 业务信息       | L1  | <br /> |
| `data`    | object / null | 空对象        | L1  | <br /> |

### 2.3 关键错误码

| 错误码     | 说明                                      |
| ------- | --------------------------------------- |
| 1435001 | 流程不存在或无权限                               |
| 1435002 | 参数错误：signFlowId 不存在或 urgedOperator 校验失败 |
| 1435003 | 业务规则冲突：发起后半小时内不可催签 / 两次催签间隔不足 10 分钟     |
| 401     | 鉴权失败                                    |
| 403     | IP 白名单不匹配                               |

### 2.4 兼容性说明

- **频率约束**（须 1:1 还原）：发起签署之后前半小时不可催签；两次催签至少间隔 10 分钟。ePaaS 须保留旧系统的频率限制口径，避免灰度期催签行为变化被调用方感知。
- 催签通知本身不产生独立 Webhook，仅触发对签署人的消息推送（依赖 data-push3 域，属依赖改造范围）。

## 3. POST /v3/sign-flow/{signFlowId}/delay

**用途**：延长已发起签署流程的截止时间。

**接口类型**：REST（后置操作类，按 signFlowId 归属路由）

### 3.1 请求参数（入参）

| 参数名                  | 位置   | 类型     | 必填 | 默认值 | 说明                   | 优先级 | 备注     |
| -------------------- | ---- | ------ | -- | --- | -------------------- | --- | ------ |
| `signFlowId`         | path | string | 是  | -   | 签署流程 ID              | L1  | <br /> |
| `signFlowExpireTime` | body | int64  | 是  | -   | 新的签署截止时间（Unix 毫秒时间戳） | L1  | <br /> |

### 3.2 响应参数（出参）

| 字段名       | 类型            | 说明         | 优先级 | 备注     |
| --------- | ------------- | ---------- | --- | ------ |
| `code`    | int32         | 业务码，0 表示成功 | L1  | <br /> |
| `message` | string        | 业务信息       | L1  | <br /> |
| `data`    | object / null | 空对象        | L1  | <br /> |

### 3.3 关键错误码

| 错误码     | 说明                                              |
| ------- | ----------------------------------------------- |
| 1435001 | 流程不存在或无权限                                       |
| 1435002 | 参数错误：signFlowExpireTime 未传或格式错误                 |
| 1435003 | 业务规则冲突：已延期过 1 次 / 新截止时间早于原截止时间 / 超出最大可延长 90 天范围 |
| 401     | 鉴权失败                                            |
| 403     | IP 白名单不匹配                                       |

### 3.4 兼容性说明

- **延期规则**（须 1:1 还原）：仅限往后延期 1 次；新截止时间在当前接口调用时间基础上最多延长 90 天，且不可早于原截止时间。
- 2023-06-30 起支持对已过期的流程延期 1 次，ePaaS 须保留此能力。
- 延期操作关联 APPID 配置项 `flowExpireTime`（ID 6091，"签署截止时间最大值"，当前 P2）--该配置约束新截止时间的上限，M-2 须在 ePaaS 侧实现读取（见 M-2 配置增量清单）。

## 4. POST /v3/sign-flow/sign-flow-list

**用途**：查询指定时间段内、指定状态/发起方/签署人的签署流程列表。仅能查询当前应用 appId 通过接口发起的签署流程。

**接口类型**：REST（后置查询类，列表查询不带 signFlowId，按 APPID 白名单 + 归属路由）

### 4.1 请求参数（入参）- SignFlowListQueryRequest

| 参数名                      | 位置   | 类型          | 必填    | 默认值 | 说明                                        | 优先级 | 备注     |
| ------------------------ | ---- | ----------- | ----- | --- | ----------------------------------------- | --- | ------ |
| `pageNum`                | body | int32       | **是** | -   | 页码，最小 1                                   | L1  | <br /> |
| `pageSize`               | body | int32       | **是** | -   | 每页条数，最小 1，最大 100                          | L1  | <br /> |
| `signFlowStartTimeFrom`  | body | int64       | 否     | -   | 流程发起时间区间-起（Unix 毫秒）                       | L1  | <br /> |
| `signFlowStartTimeTo`    | body | int64       | 否     | -   | 流程发起时间区间-止（Unix 毫秒）                       | L1  | <br /> |
| `signFlowFinishTimeFrom` | body | int64       | 否     | -   | 流程完结时间区间-起（Unix 毫秒）                       | L1  | <br /> |
| `signFlowFinishTimeTo`   | body | int64       | 否     | -   | 流程完结时间区间-止（Unix 毫秒）                       | L1  | <br /> |
| `signFlowStatus`         | body | array\[int] | 否     | -   | 流程状态过滤：1-签署中，2-完成，3-撤销，5-过期，7-拒签          | L1  | <br /> |
| `signStatus`             | body | array\[int] | 否     | -   | 签署方签署状态过滤：0-等待签署，1-签署中，2-已签署，3-等待审批，4-已拒签 | L1  | <br /> |

| ----------------- | ------ | -- | --- | --------- | --- | ------ |

## 5. POST /v3/organizations/sign-flow-list

**用途**：查询集成方企业（当前 appId 对应的企业主体）名下发起的签署流程列表。支持 API 接口发起和 e签宝 SaaS 官网发起的流程。

**接口类型**：REST（后置查询类，按 APPID 白名单 + 归属路由）

### 5.1 请求参数（入参）- OrgSignFlowListQueryRequest

| 参数名                      | 位置   | 类型          | 必填    | 默认值 | 说明                                               | 优先级 | 备注     |
| ------------------------ | ---- | ----------- | ----- | --- | ------------------------------------------------ | --- | ------ |
| `pageNum`                | body | int32       | **是** | -   | 页码，最小 1                                          | L1  | <br /> |
| `pageSize`               | body | int32       | **是** | -   | 每页条数，最小 1，最大 100                                 | L1  | <br /> |
| `signFlowStartTimeFrom`  | body | int64       | 否     | -   | 流程发起时间区间-起（Unix 毫秒）                              | L1  | <br /> |
| `signFlowStartTimeTo`    | body | int64       | 否     | -   | 流程发起时间区间-止（Unix 毫秒）                              | L1  | <br /> |
| `signFlowFinishTimeFrom` | body | int64       | 否     | -   | 流程完结时间区间-起（Unix 毫秒）                              | L1  | <br /> |
| `signFlowFinishTimeTo`   | body | int64       | 否     | -   | 流程完结时间区间-止（Unix 毫秒）                              | L1  | <br /> |
| `signFlowStatus`         | body | array\[int] | 否     | -   | 流程状态过滤：**仅支持 1-签署中，2-完成**（注意：比接口 4 少 3/5/7 三个状态） | L1  | <br /> |
| `operator`               | body | object      | 否     | -   | 操作人过滤（psnAccount/psnId，同 §4.1.2）                 | L1  | <br /> |
| `organization`           | body | object      | 否     | -   | 企业过滤（orgId/orgName，同 §4.1.3）                     | L1  | <br /> |

> **与接口 4 的差异**：本接口无 `initiator` 和 `signStatus` 过滤维度；`signFlowStatus` 枚举仅 1/2 两项。ePaaS 须保留此差异，不得与接口 4 合并语义。

### 5.2 响应参数（出参）

响应结构与接口 4 完全一致（`SignFlowListData`，详见 §4.2.2-4.2.4），此处不重复。

| 字段名       | 类型                        | 说明         | 优先级 | 备注     |
| --------- | ------------------------- | ---------- | --- | ------ |
| `code`    | int32                     | 业务码，0 表示成功 | L1  | <br /> |
| `message` | string                    | 业务信息       | L1  | <br /> |
| `data`    | object (SignFlowListData) | 同 §4.2.2   | L1  | <br /> |

### 5.3 关键错误码

## 13. POST /v3/sign-flow/{signFlowId}/copiers

**用途**：向已创建的签署流程追加抄送方。流程结束后不允许添加；autoFinish=true（自动归档）流程开启后不允许添加抄送人。

## Webhook 覆盖说明

> M-2 新增的后置操作（revoke/urge/delay/queries/sign-fields）不引入独立 Webhook，其状态变更由已有 Webhook 覆盖。sign-api.yaml `webhooks:` 段共定义 19 个事件，M-2 相关覆盖关系如下。

### 已覆盖（M-1 文档化，M-2 沿用）

| Webhook 事件           | 触发场景               | M-2 相关性                              | 文档位置      |
| -------------------- | ------------------ | ------------------------------------ | --------- |
| `SIGN_FLOW_COMPLETE` | 流程完结（含拒签/撤销/过期/完成） | **revoke 撤销后触发**（signFlowStatus="3"） | M-1 手册 §8 |

### M-2 验证候选（追加签署区引入新签署方）

| Webhook 事件             | 触发场景              | M-2 相关性                        | 建议                                              |
| ---------------------- | ----------------- | ------------------------------ | ----------------------------------------------- |
| `SIGN_MISSON_COMPLETE` | 签署方签署完成或拒签（签署方维度） | 追加签署区（接口 7）引入新签署方，其完成/拒签需通知集成方 | 建议纳入 M-2 验证集，与 SIGN\_FLOW\_COMPLETE 配合提供签署方粒度状态 |

`SIGN_MISSON_COMPLETE` Payload 关键字段（源自 sign-api.yaml）：

| 字段名                 | 类型     | 必填 | 说明                        | 优先级 |
| ------------------- | ------ | -- | ------------------------- | --- |
| `action`            | string | 是  | 固定 `SIGN_MISSON_COMPLETE` | L1  |
| `timestamp`         | int64  | 是  | 推送时间戳（Unix 毫秒）            | L1  |
| `signFlowId`        | string | 是  | 签署流程 ID                   | L1  |
| `operateTime`       | int64  | 是  | 操作时间（Unix 毫秒）             | L1  |
| `signResult`        | int    | 是  | 2-签署完成，4-拒签               | L1  |
| `resultDescription` | string | 是  | 结果描述                      | L1  |
| `signOrder`         | int32  | 是  | 签署顺序                      | L1  |
| `customBizNum`      | string | 否  | 自定义业务编号                   | L1  |
| `operator`          | object | 是  | 操作方（psnId/psnAccount）     | L1  |
| `organization`      | object | 否  | 企业信息（orgId/orgName）       | L1  |

以下 Webhook 属后续迭代（审批流/出证/解约/批量签/拟定流程），M-2 不验证：`SIGN_FLOW_INITIATE_RESULT`、`OPERATOR_READ`、`COPIER_READ`、`TRANSMISS_SIGN`、`BATCH_SIGN_FLOW_COMPLETE`、`FILE_ENCRYPT_FINISH`、`OPERATOR_CORRECT_IDENTITY`、`GET_SEAL_POSITION`、`DRAFT_MISSON_COMPLETE`、`INITIATE_APPROVAL`、`APPROVAL_TASK_START`、`APPROVAL_TASK_COMPLETE`、`APPROVAL_TASK_TRANS`、`APPROVAL_FINISH`、`EVIDENCE_REPORT_FINISH`、`SIGN_FILE_RESCISSION_INITIATE`、`SIGN_FILE_RESCINDED`。

## 附录 C：M-2 灰度路由机制（signFlowId 归属路由）

> M-2 的后置操作类接口（revoke/urge/delay/preview-download/signers-sign-fields/unsigned-files/attachments/copiers）**不携带 APPID 信息**，无法按 APPID 白名单路由，须按 signFlowId 归属系统路由。本附录对应迁移方案概要产品设计 §4.2 A-5/A-6。

### 路由规则

| 请求类型                                       | 路由判断依据              | 说明                                   |
| ------------------------------------------ | ------------------- | ------------------------------------ |
| 创建类（create-by-file 等，M-1） | APPID 白名单 + 请求体参数剖面 | 见 M-1 手册 §2.20 |
| **后置操作类（M-2 全部）**                          | **signFlowId 归属系统** | ePaaS 创建的流程 -> ePaaS；旧系统创建的流程 -> 旧系统 |
| 列表查询类（sign-flow-list / org-sign-flow-list） | APPID 白名单 + 数据可见性   | 按 appId 归属企业过滤，依赖共享数据层回写             |

### 工程实现方案（待确认）

设计概要 §4.2 A-6 列出两个参考方案，需工程侧选定：

1. **signFlowId 编码前缀区分来源系统**：ePaaS 创建的 signFlowId 携带特定前缀，灰度服务解析前缀路由
2. **signFlowId -> 归属系统映射表**：灰度服务维护映射表，创建时写入，后置操作时查询

### M-2 验收要求

- A-6 路由方案须在 M-2 外部灰度启动前就绪（设计概要 §5.2 G-1b 门控）
- 后置操作降级率须趋近于零（设计概要 §4.3 M-2 目标）：灰度上线后不希望因 ePaaS 能力缺口导致后置操作触发降级
