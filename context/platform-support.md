## 架构说明

e签宝 OpenAPI 的端分两层：

- **触发端**：集成商通过 API 服务端发起签署，无端差异
- **签署端**：签署方接收邀请后完成签署操作，支持多端，存在端差异

PRD 中涉及的端差异，**仅指签署端**的体验差异，触发端（API 调用）全端一致。

## 各端通用约束

| 约束类型 | 说明 |
|---------|------|
| 触发方式 | 签署链接由 API 服务端生成，签署方通过链接/跳转进入对应端的签署页面 |
| 域名配置 | 小程序/钉钉等端需在对应平台配置 e签宝 OpenAPI 业务域名白名单 |
| HTTPS 要求 | 所有端通信须使用 HTTPS（TLS 1.2+） |
| 文件大小 | 各端签署文件大小限制以 API 文档约束为准，端间可能存在差异 |

## PRD 中引用方式

在 PRD 的"端差异说明"章节，只列出本功能实际存在差异的端：

```markdown
## 端差异说明

> 支持端清单参考：context/platform-support.md
> 以下仅列出存在差异的端，未列出的端与 Web 端签署体验一致。

| 端 | 差异说明 |
|----|---------|
| Web 端 | 基准实现，支持完整签署功能 |
| 微信小程序 | 需通过中转接口处理文件，JSAPI 调起签署组件 |
| 钉钉端 | 需使用钉钉 JSAPI 调起，交互路径不同 |
```

若本功能全端签署行为一致，填写：

```markdown
## 端差异说明

签署端全端行为一致，无差异。
```
