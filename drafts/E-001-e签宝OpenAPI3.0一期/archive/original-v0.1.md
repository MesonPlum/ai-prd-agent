## 二、产品概述与目标

| 项目 | 内容 |
|------|------|
| 产品背景概述 | |
| 目标用户 | 所有希望集成电子签名能力的客户和生态伙伴 |
| 产品解决方案 | 1.解决电子签名的合规问题 2.增强电子签名api的场景适用性 3.减少开发者对接时的理解成本 |
| 公司的收益 | 1.避免客户或e签宝牵扯到法律纠纷 2.增强产品竞争力 3.减少交付顾问人力成本 |
| 风险点 | |

**一阶段目标**：
1. 完善用户授权&免登流程
2. 完成旧接口参数定义的优化
3. 完成新的规范下电子签名业务的MVP版本功能

## 三、名词解释

| 名称 | 解释 |
|------|------|
| 用户授权 | 用户把资源（认证信息、模板、印章等）授权给平台方应用，以便平台方利用这些资源完成业务活动 |
| 免登 | 用户把资源授权给平台方应用后，无需登录即可访问对应e签宝页面 |
| 文件模板 | 有模板唯一id，包含文件底稿+控件 |
| 流程模板 | 有模板唯一id，包含文件底稿+控件+签署人等相关配置 |
