# F-001 认证授权与免登体系（原始内容）

## 来源 1：Epic E-001 业务说明

### 核心业务逻辑

- **授权及授权校验**：满足合规要求，平台方需获取用户资源授权（authorizedScopes）后才可操作对应资源。校验规则：appId ≠ 7488 且接口 URL 含 `/v3/` 时，验证该应用是否有权操作目标用户资源。
- **免登能力**：用户完成授权后，无需登录即可通过免登链接访问对应 e签宝 页面

## 来源 2：assets/opendoc/auth3/lmfokx 用户授权与实名认证（场景介绍）

**什么是用户授权？**

根据电子签名法律法规相关要求，如需获取 e签宝 平台用户的相关隐私信息，需要提前对用户发起授权（仅支持接口形式授权），授权给当前调用方开放平台应用（AppId）使用 e签宝 用户相关资源权限（获取身份信息、印章信息等）。授权成功后，调用方调用后续业务 API 接口时需传入用户授权的 e签宝 个人或企业账号，并确保授权在有效范围内，就可以使用用户相关授权的资源权限。

**注意事项**：建议开发者本地保管好用户的账号ID与账号标识（个人用户的手机号/邮箱、企业用户的企业名称）的关联关系。

**什么是实名认证？**

实名认证是电子签名过程中必不可少的环节，通过信息核验、人脸比对、校验码回填、机构对公账户打款等方式确认身份的真实性，并反馈认证结果的服务。

对接方可以自己选择在签署前单独发起实名认证服务（可避免用户在签署中因为实名信息不符，造成签署卡点），或者用 e签宝 签署页面自带的实名认证页面。

### 两种模式

**获取机构/个人认证&授权页面链接 接口包含两种模式**：

- **授权认证模式**：包含用户授权 + 实名认证/意愿认证。用户第一次使用 e签宝 需要做实名认证，证明真实身份。第二次及以后不需要再做实名，只需做意愿认证，证明本人真实意愿。
  - 实名认证支持：人脸识别认证（支付宝人脸，腾讯云人脸），银行四要素认证，手机三要素认证。
  - 意愿认证支持：人脸识别认证（支付宝人脸，腾讯云人脸），短信验证码认证。
- **实名认证模式**：用户只需要做一次，如果用户做过 e签宝 实名认证，再次调用接口使用实名模式，接口会报错"用户已实名"。

### 自 2024-09-12 起的版本约束

部分 authorizedScopes 需要购买 e签宝 高级版或生态伙伴版本方可支持：

- 仅高级版/生态伙伴版本支持：`get_psn_identity_info`、`get_org_identity_info`、`manage_psn_resource`、`manage_org_member`、`manage_org_seal`、`manage_org_template`、`use_org_template`、`manage_org_resource`、`org_approval_info`、`apply_psn_evidence`、`apply_org_evidence`、`org_function_benefits`、`manage_org_contract`
- 仅生态伙伴版本支持：`psn_initiate_sign`、`org_initiate_sign`、`use_org_order`

### 回调通知 Action 事件类型

| Action 事件类型 | 对应事件名称 |
|---|---|
| AUTH_PASS | 实名认证通过通知 |
| AUTHORIZE_FINISH | 授权完成通知 |
| AUTHORIZE_CHANGE | 授权范围变更通知 |

## 来源 3：原 V0.1 时序图相关片段（Part1：认证&授权）

- 步骤1 查询认证&授权状态（可选）：调用「查询机构/个人认证信息」接口
- 步骤2 获取认证&授权页面链接：调用「获取机构/个人认证&授权页面链接」接口，返回认证&授权链接及流程ID
- 用户在链接内操作完成认证&授权后，e签宝 发送回调通知；保存用户 Id（psnId / orgId）
- 也可重复步骤1，主动查询用户 Id 等信息
